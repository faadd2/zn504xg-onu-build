# 编译打包流程经验教训（截至 build-24 / 201-06）

> A（主会话）侧记录，与 B 的《OpenWrt单包CI编译避坑清单_20261015.md》互补。
> 覆盖：内核补丁工作流、设备交互、发布工程、隐私纪律。

## 一、内核补丁工作流（201-06 实战）

1. **重建树法是补丁写作的唯一可靠方式**：不要凭空写 patch 上下文。建一个 git 树 = vanilla 内核 + 目标构建系统的**全部**目标补丁（ponwrt 163 个），先 `git apply`、失败的用 `patch -p1 --fuzz=3` 补打并记录，提交为"full patched state"基线，然后**直接在源文件上改**，最后 `git diff` 导出。双向 `git apply --check`（正打+反打）验证后才交付。
2. **基线漂移是头号风险**：补丁上下文随上游 commit 漂移。交付时必须钉死上游 ref（本次= huladabang/ponwrt@c3b518b）并告知编译侧核对 `ponwrt_ref`。
3. **Windows CRLF 陷阱**：git 全局 `core.autocrlf=true` 会在 checkout 时把 LF 转 CRLF，patch 文件混 CRLF 在 Linux CI 上打不上。导出后 `grep -c $'\r'` 必须为 0。
4. **诊断补丁设计**：加 `module_param` 运行时开关 + 统一前缀（`20106-ppe:`）+ `pr_info_ratelimited`，验证完 `echo 0 > /sys/module/<mod>/parameters/<switch>` 关闭，不用重刷。

## 二、设备交互（今晚实锤）

5. **Git Bash MSYS 路径转换是隐形炸弹**：`python script.py /tmp/xxx` 中**以 `/` 开头的参数**会被 MSYS 转成 Windows 路径（`/tmp/…` → `C:/Users/…/Temp/…`）再传给 python，SSH 到设备后命令莫名失败且报错位置极迷惑（设备 ash 报"can't create C:/Users/…"）。**修复：`MSYS_NO_PATHCONV=1` 前缀**；或路径放在 `-c` 字符串/配置文件里。排查口诀：**脚本失败、手动成功 = 先怀疑参数差异，抓设备端 stderr**。
6. **大文件上传 dropbear 单连接不稳**：15MB 镜像走单 SSH 通道易断。可靠方案=单连接 2MB 分块（`cat >>`）+ 失败退避 + md5 终验（`scripts/chunk_upload3.py`）。
7. **设备没有 base64/sftp**：busybox 缺 base64 applet、dropbear 无 sftp-server。拉文件用 paramiko `cat` 二进制读 + select 循环防半包（`scripts/fetch_file.py`）。
8. **HTTP 服务备用路线也有坑**：Windows 动态端口排除范围（`netsh interface ipv4 show excludedportrange tcp`）可能随时吞掉你选的端口；`cmd && cmd &` 优先级会把整条链丢进子 shell（cwd 漂移）。同一条 Bash 调用里"起服务+设备拉取+关服务"才可靠。
9. **ICMP 永不进 flow offload**：nft_flow_offload_eval 只收 TCP/UDP/GRE。用 ping 观测 PPE bind 是假象，必须真 TCP 下载。

## 三、刷机与验证

10. **刷机四件套**：刷前 `sysupgrade -b` 备份配置并**取回本地**（刷机清 /tmp）；镜像 sha256 与 Release 页对拍；上传后设备端 md5 二次校验；刷后验证清单（版本标记/四业务 up/governor/关键套件/声卡）。
11. **sysupgrade 末尾 "Connection failed" 是正常死亡**：stage2 启动即断 SSH，不是失败。等 4 分钟再验。
12. **网线永远插 1G 口**（2.5G 口 EN8811H 重启失效 bug 未修，network restart 挂死同理）。

## 四、发布与仓库工程

13. **Release 改进说明每次必写**（对照上一 tag 的 commit 列表），用户明确要求。
14. **双账号镜像**的同步责任要写在同步板上（谁领先几个 commit、谁负责收编），避免两边都等对方。
15. **删库重建前**：`git clone --mirror` 六库全历史 + Release 资产筛选镜像（itb/sha256sums/packages，跳过 .zip 双胞胎；跳过 stock——上游原味可再 derivable）。脚本 `scripts/mirror_releases.py`（断点续传+并行+终审计）。
16. **git 索引权限位**：root/ 下脚本必须 git 索引 755，否则进固件丢执行位（LuCI 假死、补丁开关失效都中过）。

## 五、隐私纪律（血泪）

17. **硬编码=泄露**：语音页"参考账号"表格把真实 IMS 号码/SIP 密码写进 JS 随固件分发。规则=任何账号/密码只能来自设备 UCI 配置，仓库里只留空模板。**git 历史里的明文删提交没用——已推送历史即泄露**，治本=轮换凭据 + 删库重建（仅最新代码作初始提交）。
18. 已知待轮换：联通 SIP 密码（git 历史）、PPPoE 账密（历史提交）、设备 root 密码如进过历史。
