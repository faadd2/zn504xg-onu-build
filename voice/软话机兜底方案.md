# 软话机兜底方案（FXS 电话口不可用时的语音退路）

> 目的：SLIC/电话口（FXS）链路修复前，用 PC/手机上的 SIP 软话机承接北京联通固话
> 的拨打与接听。本文不含任何账号密码，凭据从 `devices/ZN504XG-D/private/` 对应备份读取。

## 一、IMS 注册参数（与 baresip 相同一套）

从 `devices/PT1570-R10/backups/voip_sip_account_20261012.txt` 读取：

| 参数 | 值 |
|-|-|
| 完整 SIP ID（auth_user / 用户名） | `+8610XXXXXXXX@bj.ims.chinaunicom.cn`（带 +86 与域名，缺一不可） |
| 密码 | 见上述备份文件 |
| Registrar | `bj.ims.chinaunicom.cn:5060` |
| Outbound Proxy | `10.203.255.17:5060`（备用 `10.203.255.1:5060`） |
| 固定源端口 | **必须 5060**（随机端口时 SBC 完全沉默，零回包——已实测） |
| 注册周期 | 1800 秒 |
| 出局拨号 | 外地号码前加 0（已实测 `018608992148` 拨通；本地直拨） |

推荐软话机：**MicroSIP**（Windows，配置极简）/ **Linphone** / **Zoiper**。
MicroSIP 配置：SIP Server = `10.203.255.17`，Username = 完整 SIP ID，
Domain = `bj.ims.chinaunicom.cn`，密码见备份，Local Port = 5060。

## 二、网络前提（关键，最容易踩坑）

联通 IMS 代理是**内网地址**（10.203.255.17/23 网段），只有 voip 链路
（504 上 VLAN 3010，10.143.218.196/23）可达。软话机所在设备必须满足其一：

1. **接在 504 的 LAN 口下，由 504 转发到 voip 网段**（推荐，一次性配置）：
   - 504 上确保 lan → voip 方向防火墙放行（voip 接口默认独立 zone 时需加一条 forward）；
   - voip 接口已有联通下发的静态路由（`route` 段，指向 10.143.218.1），
     LAN 侧主机把网关指向 504 即可被转发到 10.203.0.0/16；
   - 更省事的做法：软话机 PC 的网关设成 504 的 LAN IP（DHCP 默认即是）。
   - 验证：`ping 10.203.255.17` 从 LAN 侧应通。
2. 接在原光猫 PT1570 的 LAN 下（原光猫语音桥接已配好路由时）——但项目目标是替换原光猫，不推荐作为常态。

## 三、单注册互斥（重要）

联通 IMS 对同一 SIP 账号**只允许一个有效注册**：504 上的 baresip 与软话机
**同时注册会互相踢**。使用软话机前，在 504 上停用 baresip：

```sh
/etc/init.d/baresip stop
# 用完想换回电话口（FXS 修好后）：
/etc/init.d/baresip start
```

（若 FXS 链路永久放弃，也可 `disable` 取消自启。）

## 四、与 FXS 主路线的关系

- 主路线（电话口直插话机）依赖 SLIC bring-up，当前卡在 ZSI 总线零应答
  （见 `../voice/README.md` 与 SESSION-SYNC.md），由 004 补丁（bus_slot 运行时扫描）
  继续排查。
- 本兜底方案**不依赖** SLIC/FXS，任何固件版本都可用；通话音质/延迟与
  IMS 网络质量一致（baresip 外拨已实测打通，语音编码 G.711）。
- 后续若 SLIC 修复，baresip 的 IMS 注册成果（完整 SIP ID + 固定 5060 端口
  两个关键条件）原样适用于 FXS 路线。

## 五、已知限制

- 软话机接听依赖 PC 常开+软件常驻，不如话机可靠；DECT 无绳话机方案
  （FXS 修好后）仍是终态。
- 北京联通 SBC 对异常注册有静默期（10-17 实测），注册失败时等 5~10 分钟自动重试。
